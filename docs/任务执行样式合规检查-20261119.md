# 任务执行模块：样式与共享组件合规检查

状态：本报告列出的六类问题已完成本批整改；以下原始检查及当时行号保留，整改和实际验证见文末。

检查日期：2026-11-19（Asia/Shanghai）。范围包括临时任务、流程编排、流程编辑、执行记录与详情、临时任务详情抽屉及其操作菜单。

本批为源码审查，没有修改产品代码，没有启动服务、使用账号或执行模型。本次没有重跑构建、浏览器或后端验收；下述视觉影响依据 DOM、适配器和 CSS 规则推导，实际截图与交互回归留待修复批次。

## 结论与判定基线

存在不合规及样式冲突，原因同时包括未复用通用组件、共享组件接入方式过于粗放，以及旧深色样式未完整归入主题。

依据 AGENTS.md、进度&规则.md、README.md、docs/工程边界.md、底层能力/交互组件/README.md、底层能力/表格组件/README.md 和 web/src/index.css。工程明确允许保留原生业务控制器，通过共享 native-controls 与 native-dialog 迁移；不能仅因页面使用原生 DOM 就判违规。

已正确接入的部分：web/src/scheduler-frame.ts:3–4 引入共享 native-dialog、native-controls，:36–37 在加载控制器前接入；services/ai-gateway/public/dialog.js:35 起优先调用平台弹窗桥接。按钮、普通输入框、文本域以及通用确认/输入弹窗不是完全未复用。

## 发现

### 1. 优先修复：通用按钮适配侵入业务尺寸与按钮语义

- 底层能力/交互组件/src/ui/native-controls.ts:12–17 对所有 button 无差别套用 size=default；只区分 primary、danger，其余全部视为 outline，原 ghost、text-btn、icon-btn 没有对应映射。
- 底层能力/交互组件/src/ui/button.tsx:23–24 的默认尺寸包含 h-8；web/src/scheduler.css:14 又对所有已适配按钮强加 min-height:32px、边框、背景和字体。
- services/ai-gateway/public/app.js:690 的 adhoc-row、:3522 的 run-tab 都是多行记录按钮，原布局没有显式高度（layout.css:2012、:2221），会获得普通按钮的固定高度约束。
- layout.css:1998 的技能标签高 22px，其移除按钮在 :2002 为 16px；:2435 的节点按钮为 18px，却统一受到至少 32px 高度约束。

这属于“已经调用共享能力，但接法破坏布局”，不是缺少 Button import。应在共享适配层明确按钮变体、尺寸与业务复合控件边界，保留记录行的内容高度，避免继续逐页追加全局覆盖。

### 2. 通用选择器没有复用共享 Select；流程选择器自行实现弹出列表

- scaffold.html:66 的员工选择、:74 的归档选择及 :115 的流程归档选择为原生 select。
- app.js:4106、:4140–4146、:4158 动态生成流程检查器 select。
- native-controls.ts:18–25 不处理 select；scheduler.css:20 只是给 select 涂主题样式，并未调用共享 Select。
- scaffold.html:101–110 的流程选择器使用隐藏 select、自建 trigger/listbox；app.js:3206–3239 自行生成选项和开关，:7408–7429 自行处理点击、外部点击与 Esc。

共享 select.tsx 已提供 Radix 选择器。自建流程选择器未实现同等的列表键盘导航、打开后选项焦点管理；单纯有 role 与 aria-expanded 不等于复用了底层交互。修复需保留现有 select 值及 change 事件协议，可在共享层增加原生控制器桥接，不应复制另一份 Select 实现到业务页。

### 3. 复选框仍使用浏览器原生实现，未复用共享 Checkbox

- scaffold.html:69 的“允许写文件”为原生 checkbox。
- app.js:4153 的步骤检查点和 :4368 的变量必填为动态 checkbox。
- native-controls.ts:18 明确跳过 checkbox；layout.css:1991、:2622 仅以 accent-color 调色。

缺少统一 Checkbox 的外观与交互入口。迁移时必须保留 checked、change 事件与原先业务含义，尤其不能改变允许写文件、检查点和必填的保存协议。

### 4. 任务详情抽屉自行实现，没有复用共享 Sheet

- scaffold.html:298–310 自建 aside.drawer 与 scrim。
- app.js:1178–1209 以 class 和 aria-hidden 控制开关，同时处理流订阅。
- scheduler.css:25 仅覆盖 drawer 的颜色、圆角等，不会将其变成共享 Sheet。

共享 sheet.tsx 已提供基于 Radix Dialog 的抽屉。当前开关路径未接入其焦点圈定、关闭后焦点恢复等能力；不能将背景/圆角覆盖视为组件迁移完成。修复应只替换通用容器，保留任务详情渲染、事件流与关闭清理。

### 5. 任务详情“更多”菜单自行实现，没有复用共享 DropdownMenu

- app.js:1315–1350 的 moreMenu 手动创建 trigger、panel、外部点击与 Esc 监听。
- 共享 dropdown-menu.tsx 已存在；此路径没有调用它。

该函数属于通用菜单交互的重复实现。当前实现没有共享菜单的方向键导航及完整焦点管理。应桥接共享 DropdownMenu，同时保留现有业务操作、危险操作确认及可用状态。

### 6. 固定深色样式未归入宿主主题，部分表单仍被旧高优先级规则覆盖

- layout.css:2113 的流程选择菜单使用固定深色渐变，scheduler.css 没有针对该容器的主题映射。
- layout.css:2421 的流程画布节点使用固定深色渐变，:2465 的条件节点同样残留固定深色背景；现有 .flow-canvas 覆盖不覆盖节点本身。
- layout.css:2598 的 select option 固定背景 #0d1a2b，但文字取已映射到宿主主题的 --text-primary，浅色主题存在深底深字风险；原生 option 的最终呈现还受操作系统影响。
- layout.css:2577–2586、:2602–2618 的检查器规则具有比 scheduler.css:20 更高的选择器优先级，仍可覆盖共享输入/文本域的字体、边框和背景。
- scheduler.css:2 将宿主同名 --accent 重定义为 --primary；index.css 的 --color-accent 又引用 --accent，使调度文档内共享组件的 accent 色偏离宿主定义。

这不是单靠补几个组件 import 就能解决的问题。需收敛旧视觉规则，使用宿主主题变量；业务成功、失败、运行中、检查点、条件分支等语义仍要保留。

## 不应直接判为违规的部分

- 流程画布、拖拽节点、连线、执行步骤、事件日志属于业务专用布局，共享清单没有对应完整业务组件；允许保留，但其内部通用控件和主题必须统一。
- 临时任务最近记录是任务摘要入口，运行记录是主从详情导航；目前不宜直接认定二者必须改成 DataTable。通用管理列表应使用 DataTable，但不能仅按“有列表”就破坏这里的任务导航语义与布局。
- 通用弹窗存在旧 fallback 实现，但 V2 入口在控制器加载前设置 platformOpenDialog，正常路径实际调用共享 Radix 弹窗；本批不将 fallback 的存在记为未复用。

## 建议修复顺序与后续验证

1. 修正共享原生按钮适配和尺寸冲突，再收敛任务模块旧视觉规则。
2. 在共享层补齐原生控制器到 Select、Checkbox、Sheet、DropdownMenu 的适配；业务代码只处理数据及回调。
3. 保留任务/流程接口、草稿、状态、权限、节点位置、工作副本和保存协议。
4. 修改前端后执行 npm --prefix web run build；使用临时数据与合成任务验证浅/深主题、390px 布局、多行任务记录、运行记录、技能删除按钮、流程选择、检查器、抽屉和菜单的鼠标/键盘行为。
5. 浏览器验证需包括焦点进入、Esc 关闭、焦点返回、禁用/危险/选中状态、草稿和表单值保留。本批未进行这些复验，历史七页浏览器通过不能替代本批结论。
