# 企划设计BG平台 · WorkBuddy 第一轮接入版

基于 V3.0 原型及 `WorkBuddy_Round1_Integration_Research_V1.0.zip` 优化。平台数据保存在本目录的 `platform.sqlite3`，首次启动自动创建。**当前只接入 本地工作台以 GD《企划设计BG｜12大维度最新布局与交互规则》V1.0（2026-11-10）为布局依据。12 维共享预览／工作顶部栏、预览左侧目录、右侧三视图，以及工作模式的保存与版本管理。预览默认只读已应用成果，未应用内容可从工作区和版本管理查看。历史 Markdown 可从文字纯享版读取。

DIM-01「产品线齐全」采用「行业生态布局全景／同类产品规划」两个连续章节。矩阵支持三行、三至五列及独立数据卡片，同类产品按分类以每行最多七款、每页最多四行展示。旧版成果会映射到新版展示；旧三章节可从原历史版本查看。未应用修改存入项目专属的 SQLite 草稿；顶部「保存并应用」整维校验。DIM-01 原图由当前浏览器保存。

DIM-02「行业应用场景」已更新为最新的「完整页面交付包 V1.0」交互：唯一大场景及主图、可增删排序的业务系统与设备、产品状态标签、可增删排序的细分业务场景、各场景独立拓扑原图、场景特点／需求／痛点及关键功能设计目标。平台保留统一的顶部维度与模块切换、右侧内容／文字／调研视图、历史版本和全屏工作模式。工作模式的修改自动暂存到本机 SQLite，刷新后可继续编辑；只读预览与文字纯享版读取已应用版本。「保存并应用」会检查名称、拓扑图及分析内容，成功后生成可预览、恢复的历史版本。上传的主图、设备图和拓扑图随草稿及正式版本保存在本机。旧版 DIM-02 项目内容与历史版本继续保留，并在新版页面展示；旧版没有的拓扑图需在工作模式补齐后才能应用新版。

DIM-03「证书资质全」采用六字段无分类资质总表，每页最多 15 条。工作模式支持原位编辑、插入、逐行删除、排序及多格粘贴。

DIM-04「技术先进」在「技术先进」八列表与「先进性分析」两个模块间切换。先进性分析采用技术目录与所选技术的论点、证据详情。旧专题版本可从版本管理打开。

DIM-05「功能强」呈现功能架构、完整功能清单、核心功能与亮点、竞品功能对标。DIM-06「性能稳」采用八字段连续单表，支持工作模式原位编辑、批量插行和拖动行高、列宽；旧数据未提供的产品名留空，由用户核对填写。DIM-07「AI 智慧力」呈现六字段 AI 功能规划单表。示例资料在工作模式中需核对后才可应用。

DIM-08「成本优势」按 V2.0 示例展示顶部我司单台 BOM、可展开的七项物料明细、三款竞品的人民币成本对比和自动计算的综合结论。竞品售价的“查看依据”保持外链；报价来源属于示例，正式使用前需逐条核验。工作模式可修改我司成本、BOM 明细、竞品品牌型号、售价及来源；估算成本和优势判断随数值重算。

DIM-09「控标能力强」按 V3.0 示例展示三品牌共 30 条原始条款与 6 个控标点，保留全文搜索、类型筛选、展开收起、关联条款定位及 CSV 导出。工作模式可编辑条款正文与状态、控标点五项内容。DIM-10「应标能力强」按 V1.0 示例展示四态统计、11 项主题的三品牌完整原文对照和各品牌共 18 条原始参数，只有部分品牌覆盖的主题显示来源标记；修改原文或应标状态后，统计与对照从同一数据同步更新。两维的样例数据分别来自各自示例包，不会被当作同一招标项目的真实共用数据。

DIM-11「外观高档大气」按示例保留六款竞品的三列单图画廊，图片等比例完整显示；点击图片后，右侧 35% 覆盖式详情展示设计定位、设计风格、应用环境和核心设计语言。工作模式侧栏可修改产品文字、四项设计描述，并通过本机图片或链接替换示意图。DIM-12「体验感好」按示例保留固定产品名称列、四个一级维度、五个彩色分类和 18 项横向矩阵；支持快捷定位、四态规划选择、待选择项定位与连续填写、完成横幅及文字格编辑。

维度 8–12 均接入平台统一导航、右侧三视图、全屏工作模式、侧栏编辑和项目专属 SQLite 历史版本。示例材料不自动进入正式企划正文，也不计入正文完成度。统一呈现规则见 `dimension-assets/12维统一呈现规则.md`。已运行的旧服务须重启后才能加载新静态页面路由。

## 第一轮操作

1. 创建项目，进入 DIM-01，主动开启研究周期，点击「准备第一轮研究任务」。平台会创建独立 `runId` 和 `round1_runs/<项目>/<维度>/<周期>/<runId>/WorkBuddy执行指令.md`，**不会创建假正式任务包**。
2. 在 WorkBuddy 中确认两个样例 Skill 已安装并启用，将执行指令交给 WorkBuddy，并让它在显示的受控目录中写出 `正式研究任务包.md`。平台目前无法自动证明桌面 WorkBuddy 真正加载了哪些 Skill。
3. 返回工作台点击「检查输出文件」。仅 UTF-8、正确 frontmatter、七个章节、至少两个 GPT 任务及映射等规则通过后，才能登记双 Skill 的**人工核验记录**。
4. 核对真实 WorkBuddy 会话或日志中两个 Skill 的实际调用，再填写会话或日志依据，点击「登记人工核验」及「发布正式任务包」。正式版本和 SHA-256 将不可变地保存到 SQLite，旧版本留存。GPT 入口仍由用户主动启动。

`WORKBUDDY_ACCESS_TOKEN` 环境变量存在且已获官方 `user.localassistant.readable` 与 `user.localassistant.invokable` 授权时，运行卡会出现单独的「通过官方 API 投递」按钮。点击后只表示消息投递，**不代表 Skill 已执行或 MD 已生成**。发送超时或状态不确定时平台不会自动重投。令牌仅由服务端进程读取，不写入 HTML、SQLite 或任务 MD。

## 本轮边界

- 仅 DIM-01 有样例专业 Skill；其它 11 维度不能借用它。样例位于 `workbuddy_sample_skills/`，平台不会擅自安装到 WorkBuddy。
- 当前环境未找到 Open API 令牌，且尚无真实 WorkBuddy 会话、双 Skill 调用证据或真实产物；本轮已验证本地交接、结构核验和发布事务，**未宣称自动执行闭环已经通过真实 POC**。
- 第二轮整合、补研、自动目录监听和完整 WYSIWYG 仍待后续实施。正式正文不会被第一轮自动修改。

## 验证

运行 `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v`。测试覆盖 WorkBuddy 第一轮的幂等准备、无假产物、错维度拒绝、MD/Skill 证据门槛、文件变更后证据失效、版本保留和 GPT 锁定，也覆盖 DIM-03 至 DIM-12 的字段结构、可编辑值与历史版本不可改写约束。官方 API 请求格式取自 [WorkBuddy 本地助理 Open API](https://open.workbuddy.cn/docs/openapi)；实际 OAuth 授权需符合[第三方应用要求](https://open.workbuddy.cn/docs/third-party-app)。
MD 和项目数据仅在本机 SQLite 与受控运行目录保存。项目外文件不会被平台自动删除。
